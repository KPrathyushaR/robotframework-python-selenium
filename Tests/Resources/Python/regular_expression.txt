1. Email Validation Regex

Regex:

^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$

Suppose the interviewer asks:
Can you explain this regex?
You should explain it from left to right.
Regex Part	Meaning
^	Start of the string. Ensures matching begins at the first character.
[A-Za-z0-9._%+-]	Allows uppercase letters, lowercase letters, digits, ., _, %, +, and - in the username.
+	One or more of the previous characters are required.
@	The email must contain exactly one @ symbol.
[A-Za-z0-9.-]	Allows letters, digits, dots, and hyphens in the domain name.
+	Domain must have at least one character.
\.	Matches a literal dot (.). The backslash is needed because . normally means "any character".
[A-Za-z]	Top-level domain should contain only letters.
{2,}	At least 2 letters (e.g., com, org, in).
$	End of the string. Prevents extra characters after the domain.
Example 1
john123@gmail.com

Breakdown
john123

Matches
[A-Za-z0-9._%+-]+

Then
@

Matches
@

Then
gmail

Matches
[A-Za-z0-9.-]+

Then
.

Matches
\.

Then
com

Matches
[A-Za-z]{2,}

Whole string matches ✔

Example 2
john@@gmail.com

Fails because there are two @ symbols.

Example 3
@gmail.com

Fails because

[A-Za-z0-9._%+-]+

requires at least one character before the @.

Example 4
john@gmail

Fails because there is no .com, .in, .org, etc.

Interview Answer

"The regex starts with ^, which marks the beginning of the string. The first character class allows letters, numbers, dots, underscores, percent signs, plus signs, and hyphens for the username, and + ensures at least one character is present. Then @ separates the username and domain. The next character class allows letters, numbers, dots, and hyphens for the domain name. \. matches the literal dot before the extension, and [A-Za-z]{2,} ensures the extension contains at least two alphabetic characters. Finally, $ ensures there are no extra characters after the extension."

2. IPv4 Address Validation

Regex

^((25[0-5]|2[0-4][0-9]|1?[0-9]{1,2})\.){3}(25[0-5]|2[0-4][0-9]|1?[0-9]{1,2})$

An IPv4 address has four numbers (octets), each between 0 and 255, separated by dots.

Example

192.168.1.100

Think of it as

192
168
1
100

Each part must be between 0 and 255.

Breaking the regex

Start of string

(

Start a group.

25[0-5]

Matches

250
251
252
253
254
255

Why?

25

is fixed.

[0-5]

allows only

0
1
2
3
4
5

So

256
257
259

are rejected.

Next

2[0-4][0-9]

Matches

200
201
...
249

Why?

2

is fixed.

[0-4]

allows

0
1
2
3
4

The last digit

[0-9]

allows any digit.

So it covers

200–249

Next

1?[0-9]{1,2}

This covers the remaining valid values:

0–9
10–99
100–199

Explanation:

1? means the leading 1 is optional.
[0-9]{1,2} means one or two digits.

Together, this branch is intended to cover values up to 199.

Then

|

means OR.

So one octet can be:

250-255
OR
200-249
OR
0-199

Then

\.

Matches a literal dot.

Then

That gives:

Finally

(25[0-5]|2[0-4][0-9]|1?[0-9]{1,2})

Matches the last octet, but without a trailing dot.

Common Follow-up Interview Questions
Q1. Why do we use \. instead of .?

Answer: In regex, . means any single character. To match an actual dot (.), we escape it as \..

Q2. Why do we use ^ and $?

Answer: They anchor the match to the beginning and end of the string, ensuring the entire input matches the pattern rather than just a part of it.

Q3. What is the difference between *, +, and ??
Symbol	Meaning	Example
*	Zero or more	ab* → a, ab, abb
+	One or more	ab+ → ab, abb
?	Zero or one	colou?r → color, colour

1. Email Validation
Regex
^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$
Breakdown
Part	Meaning
^	Start of the string
[A-Za-z0-9._%+-]+	Username: letters, digits, ., _, %, +, - (one or more)
@	Mandatory separator between username and domain
[A-Za-z0-9.-]+	Domain name (letters, digits, dots, hyphens)
\.	Literal dot before extension
[A-Za-z]{2,}	Domain extension with at least 2 letters (com, org, in)
$	End of the string
Valid
john@gmail.com
abc_123@yahoo.in
Invalid
@gmail.com
john@@gmail.com
john@gmail
Interview Explanation

This regex validates an email by checking for a valid username, exactly one @, a valid domain, a literal dot, and a domain extension of at least two letters.

2. IPv4 Address Validation
Regex
^((25[0-5]|2[0-4][0-9]|1?[0-9]{1,2})\.){3}(25[0-5]|2[0-4][0-9]|1?[0-9]{1,2})$
Breakdown
Part	Meaning
25[0-5]	250–255
2[0-4][0-9]	200–249
1?[0-9]{1,2}	0–199
`	`
\.	Literal dot
{3}	Repeat first three octets
Last group	Fourth octet
^...$	Entire string must match
Valid
192.168.1.1
255.255.255.255
10.0.0.1
Invalid
256.10.20.30
192.168.1
192.168.1.300
Interview Explanation

An IPv4 address has four octets separated by dots. Each octet must be between 0 and 255, and the regex enforces that range.

The regex supports optional protocol, optional www, a valid domain, an extension, and an optional path.

7. Password Validation
Regex
^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&]).{8,}$
Breakdown
Part	Meaning
(?=.*[a-z])	At least one lowercase letter
(?=.*[A-Z])	At least one uppercase letter
(?=.*\d)	At least one digit
(?=.*[@$!%*?&])	At least one special character
.{8,}	Minimum length of 8 characters
Valid
Hello@123
Pass#2025
Invalid
hello123
HELLO123
Hello123
Interview Explanation

Lookaheads ((?=...)) ensure the password contains each required character type without consuming characters.

8. Date Validation (DD/MM/YYYY)
Regex
^(0[1-9]|[12][0-9]|3[01])\/(0[1-9]|1[0-2])\/\d{4}$
Breakdown
Part	Meaning
0[1-9]	Days 01–09
[12][0-9]	Days 10–29
3[01]	Days 30–31
/	Separator
0[1-9]	Months 01–09
1[0-2]	Months 10–12
\d{4}	Four-digit year
Valid
25/12/2025
01/01/2026
Invalid
32/12/2025
15/13/2025

Note: This validates the format only. It won't reject dates like 31/02/2025; additional logic is needed for calendar validation.
