⏱️ 3–4 min: AI / Kiro / MCP
Why Kiro?

“Kiro helps us accelerate automation development by using business requirements and automation guidelines to assist in generating automation scripts. It reduces repetitive manual coding effort.”

What is the MD file?

“The MD file is a Markdown file where we maintain business requirements, feature details, scenarios and automation/framework guidelines. It provides reusable instructions for the AI-assisted automation workflow.”

Why MD file?

“It centralizes the business and automation rules, so we don't need to provide the same instructions repeatedly and it helps maintain consistency.”

What is MCP?

“MCP, or Model Context Protocol, provides a standardized way for an AI application such as Kiro to interact with configured external tools and data.”

Remember:
Kiro = AI-assisted development environment
MCP = standardized connection/protocol
MCP Tool = specific capability exposed to Kiro
MD = requirements + business/automation instructions

How do you validate AI output?

“I don't blindly accept the generated script. I review the code, validate locators, POM structure, business logic, test data and assertions. Then I execute it and compare expected versus actual results.”

If AI generates wrong code?

“I identify whether the issue is with the requirement, prompt, locator, business logic or test data. I correct the appropriate input or script, regenerate or update it, review the changes and execute it again.”

⏱️ 4–5 min: L3 Scenario Questions
100 tests suddenly fail

“I don't fix them one by one. First I analyze logs and reports and group failures by common root cause. Then I prioritize business-critical failures and fix common issues such as locator or framework changes first. I separate automation, application, data and environment issues and collaborate with the respective teams.”

Production defect escaped

“I perform root-cause analysis, identify why the scenario was missed, add the missing test coverage, automate it if suitable and add it to regression.”

Developer rejects your defect

“I reproduce it, provide evidence, verify the requirement and acceptance criteria, discuss it with the developer and involve the BA/PO if clarification is needed.”

Everything is failing in Jenkins

“I first determine whether it's a common environment or pipeline issue before investigating individual test cases. I check Jenkins logs, dependencies, configuration, environment variables, browser setup and connectivity.”

Jenkins → CI/CD and automated execution.
Git → source-code management.

API → status + body + headers + schema + business validation.

Authorization → what you can access.
Kiro → AI-assisted automation development.
MCP → standardized connection to external tools/data.
AI output → always review, execute and validate; don't blindly trust it.
🎯 Final interview strategy

When the client asks “Why?”, answer with the business reason.

When they ask “How?”, give the technical flow.
When they ask “What if it fails?”, explain root cause → evidence → fix → rerun → regression.
