Most Asked Interview Questions
Q1. What is Selenium?

Answer:
Selenium is an open-source browser automation tool used to automate web application testing. It supports multiple browsers (Chrome, Firefox, Edge, Safari) and multiple programming languages such as Python, Java, C#, and JavaScript.

Q2. What is WebDriver?

Answer:
WebDriver is the Selenium component that communicates directly with the browser and performs user actions like clicking, typing, selecting, and navigating.

Q3. Why is Selenium popular?

Answer:

Open source
Cross-browser support
Cross-platform support
Multiple language support
Easy integration with testing frameworks and CI/CD tools
Q4. Which locator is best?

Answer:
Prefer this order:

ID
Name
CSS Selector
XPath

IDs are usually the fastest and most reliable when available.
Interview Question
Q: What is the difference between driver.close() and driver.quit()?

Answer:

driver.close()	driver.quit()
Closes only the current browser window.	Closes all browser windows opened by Selenium and ends the WebDriver session.

Example:

If Selenium opens 3 browser tabs:

driver.close() closes only the active tab.
driver.quit() closes all tabs and exits the browser completely.

Part 1: Why Do We Need Waits?

Imagine Selenium opens a website:

Selenium
   |
   ↓
Open Login Page
   |
   ↓
Find Username Box
   |
   ↓
Enter Username

But the website takes 3 seconds to load.

Selenium is very fast.

It searches immediately:

0 seconds → Find username element
             |
             ↓
          Element not available
             |
             ↓
          Error ❌

Error:

NoSuchElementException

So we tell Selenium:

"Wait until the element is available."

Part 2: Types of Waits

Selenium has three common waits:

Wait	Purpose	Usage
time.sleep()	Fixed wait	Beginners only
Implicit Wait	Global wait	Basic automation
Explicit Wait	Condition-based wait	⭐ Recommended
1. Static Wait - time.sleep()

Example:

import time

time.sleep(5)

Meaning:

"Stop execution for exactly 5 seconds."

Problem with sleep()

Example:

Page loads in:

2 seconds

But you wrote:

time.sleep(10)

Selenium waits:

2 sec loading
+
8 sec unnecessary waiting

Your automation becomes slow.

Another problem:

If page takes:

12 seconds

Your test fails.

Because:

time.sleep(10)

is finished.

Interview Answer
Q: Why should we avoid time.sleep()?

Answer:

"Because it is a hard-coded wait. It waits for a fixed amount of time regardless of whether the element is available or not. Explicit waits are preferred because they wait only until a required condition is met."

2. Implicit Wait

Implicit wait tells Selenium:

"Wait this much time whenever you search for an element."

Syntax:

driver.implicitly_wait(10)

Example:

from selenium import webdriver

driver = webdriver.Chrome()

driver.implicitly_wait(10)

driver.get("https://www.google.com")

Meaning:

Whenever Selenium searches an element:

Maximum wait = 10 seconds

Example:

driver.find_element(By.ID,"username")

Selenium:

Element available immediately?
       |
       Yes → Continue

       No
       |
       Wait up to 10 seconds
Advantages

✅ Simple
✅ Applies globally

Disadvantages

❌ Cannot wait for specific conditions
❌ Can slow execution
❌ Less control

3. Explicit Wait ⭐⭐⭐⭐⭐

This is the most important interview topic.

Explicit wait:

"Wait until a specific condition happens."

Examples:

Wait until:

Element is visible
Element is clickable
Alert appears
Text appears

Syntax:

WebDriverWait(driver, timeout).until(condition)

Import:

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
Example: Wait Until Button is Clickable
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC


wait = WebDriverWait(driver,10)

login_button = wait.until(
    EC.element_to_be_clickable(
        (By.ID,"login")
    )
)

login_button.click()
Explanation
wait = WebDriverWait(driver,10)

Maximum waiting time:

10 seconds
EC.element_to_be_clickable()

Condition:

"Is this button ready to click?"

If available after:

3 seconds

Selenium continues immediately.

It does NOT wait remaining 7 seconds.

Common Expected Conditions
1. Element Visible
EC.visibility_of_element_located()

Example:

element = wait.until(
EC.visibility_of_element_located(
(By.ID,"username")
))
2. Element Clickable

Most used.

EC.element_to_be_clickable()
3. Element Present
EC.presence_of_element_located()
4. Title Contains
EC.title_contains("Dashboard")
Real Login Example With Explicit Wait
import time

from selenium import webdriver
from selenium.webdriver.common.by import By

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC


driver = webdriver.Chrome()

driver.get(
"https://the-internet.herokuapp.com/login"
)

driver.maximize_window()


wait = WebDriverWait(driver,10)


username = wait.until(
EC.visibility_of_element_located(
(By.ID,"username")
)
)

username.send_keys("tomsmith")


password = driver.find_element(
By.ID,
"password"
)

password.send_keys(
"SuperSecretPassword!"
)


login = wait.until(
EC.element_to_be_clickable(
(By.CSS_SELECTOR,"button.radius")
)
)

login.click()


time.sleep(3)

driver.quit()
Exception Handling
1. NoSuchElementException

When Selenium cannot find an element.

Example:

driver.find_element(By.ID,"wrong")

Error:

NoSuchElementException
2. TimeoutException

When explicit wait reaches timeout.

Example:

wait.until(
EC.visibility_of_element_located(
(By.ID,"abc")
)
)

After 10 seconds:

TimeoutException
Handling Exceptions Example
from selenium.common.exceptions import TimeoutException


try:

    element = wait.until(
    EC.visibility_of_element_located(
    (By.ID,"username")
    ))

except TimeoutException:

    print("Element not found")
Important Interview Questions
Q1. What are different types of waits in Selenium?

Answer:

"Selenium provides implicit wait and explicit wait. Additionally, Python's time.sleep() can be used as a static wait, but it is not recommended for production automation."

Q2. Difference between implicit and explicit wait?
Implicit Wait	Explicit Wait
Applies globally	Applies to specific element
Waits for element presence	Waits for condition
Less flexible	More flexible
Simple	Recommended
Q3. Which wait do you prefer in automation framework?

Answer:

"I prefer explicit waits because they improve test stability by waiting for specific conditions like visibility or clickability instead of adding unnecessary delays."

Q4. Why does Selenium fail sometimes even though the element exists?

Answer:

"The element may exist in the DOM but may not be loaded, visible, or clickable. We handle this using explicit waits."
